# 晴屿 1.0 测试报告

测试日期：2026-10-28。环境：Apple Silicon Mac、macOS 26.3.1、Swift 6.3.2。

## 结论与边界

六个模块已实现，并按模块完成业务测试与界面检查。自动断言 **35 项通过、0 项失败**；原生界面已实际操作新增、编辑草稿、课表 CSV 预览导入、手动备份和页面跳转。测试数据位于独立 `/tmp/qingyu-*` 目录，正式用户空间不放入演示记录。

以下结果不等同于全部 PRD 条目已经最终验收：尚未重启用户电脑，尚未完成真实课表截图导入，未实际登录验证开机启动，动画手感需用户本人确认。主线程显示回调测试不能证明 GPU 稳定 60 fps。

## 原生界面与离线操作

实际通过 macOS 辅助功能操作真实窗口，直接检查磁盘快照及校验和：

- 创建课程 `GUI course verified`，确认地点 `Room 308`。
- 创建训练安排、长期目标、个人活动，并确认对应记录落盘。
- 编辑草稿 `Draft survives reopen`，退出重开后继续编辑。
- 使用原生文件选择器打开 CSV，进入预览后确认导入 `GUI CSV import`，核对双周、地点及唯一记录。
- 点击“立即备份”，核对生成完整备份文件。
- 以上数据复核脚本：`scripts/verify_ui_data.py`，只读独立测试空间。
- 最终版在 `(deny network*)` 的 macOS 沙箱策略下启动，六个模块可用；再次通过实际界面新增课程、训练安排、目标、活动并备份，校验数据。控制组 curl 在相同策略下无法解析主机。没有切断用户电脑的网络。
- 最终版采用原生页面容器：只挂载当前页，同时保留各页视图与滚动状态。编辑弹窗在该容器下重新验证，能打开并保存。

此轮修复了原生窗口首次不显示、编辑弹窗不挂载、文件面板阻塞、隐藏页面重复渲染毛玻璃、侧栏降低透明度失效等问题。草稿丢弃写入失败时保留编辑器并显示错误，Escape 关闭编辑器保留草稿。

## 后台与系统通知

- 主窗口关闭后进程继续运行，20 秒提醒检查仍执行；主窗口可重新打开。
- 当前系统返回通知权限为 `authorized`。测试未修改系统通知权限。
- 在独立空间建立到期训练，关闭主窗口后，macOS 通知中心 API 确认测试通知已送达，去重记录已写入。随后清理本条测试通知。
- 系统横幅是否可见仍受通知样式及专注模式影响；未把“送达通知中心”当作实际看到横幅。通知点击后的系统交互路径仍待用户实际确认。
- 登录后启动已接入 `SMAppService`；没有替用户更改登录项，也未退出登录测试。

原始证据：`qa/notification-delivery.txt`、`qa/runtime-check.txt`。

## 视觉与性能

实际使用系统窗口截图检查毛玻璃；未用离屏截图判断系统材质。

- 已检查六个模块、深浅主题、最小窗口、长标题与空状态。
- 首页六个圆形入口固定布局，悬停与按下有轻量反馈；页面转入采用 240 ms 淡入。
- 页面退出后仅移除显示层，保留原生页面实例；无全屏持续动画或后台背景动画。
- 支持系统与 App 的减少动态效果、降低透明度。
- 性能测试在 24 次连续页面切换期间采集主线程显示回调，目标 60 Hz；本次中位间隔 16.67 ms、P95 27.57 ms、最大 136.93 ms；完整数值见原始报告。统计包含首次构建页面，不能当作 GPU 渲染帧率。仍可能有首次打开复杂页面的短时峰值，不能宣称稳定 60 fps。

## 复现

```sh
swift run CampusChecks
zsh scripts/package.sh release
python3 scripts/verify_ui_data.py
open -n -W dist/晴屿.app --args --qa --data-dir /tmp/qingyu-runtime-recheck --runtime-check --theme 深色
open -n -W dist/晴屿.app --args --qa --data-dir /tmp/qingyu-notification-recheck --notification-check
```

`--qa` 必须配合独立 `--data-dir`。通知探针仅在已有授权时验证送达，不弹出授权请求。复现界面数据脚本需要先完成相应的真实界面操作；不会创建记录冒充测试成功。
